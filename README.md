# 扫描件转 Word

把**扫描版 / 拍照版 PDF**（没有文字层、复制不出字的那种）转换成**保留版式、可直接编辑**的 `.docx`，
也能只把里面的**表格导成 `.xlsx`**（逐文件可选，默认 Word）。

全部处理在本机完成，**不联网、不上传、不调用任何云端 API**。

---

## 它做了什么

```
                                            ┌─> Word  python-docx  (默认, 保版式)
PDF ──渲染──> 页图 ──OCR──> 文字+坐标 ──版面重建─┤
   PyMuPDF        RapidOCR         规则引擎+框线  └─> Excel openpyxl    (只导表格)
```

OCR 只能给出「这一行字在哪个坐标」，把它还原成有结构的 Word 才是难点。本工具的版面重建做了这些：

| 处理 | 说明 |
|---|---|
| **框线表格还原** | 原件画了框线的表格**照框线还原行列**：缺哪条内部框线，那里在原件里就是一个**合并单元格**，还原出来照样是合并的（Word 里真合并，Excel 里 `merge_cells`）。一格里排了三行字也还是一格——按文字间距猜列时它必然被拆成三行，这是扫描件转表格最常见的坏结果。框线用形态学开运算取，厚度按「面积÷长度」判，不看外接框：扫描件总带零点几度歪斜，一条 1500 px 的横线外接框就有七八像素高。汉字竖笔跟框线一样细一样直，靠「两端都搭在横线上」+「不落在 OCR 文字框里」两道判据滤掉，一页正文能因此少认三百多条"竖线" |
| **多列表格还原** | 无框线的多列版面（`序号 \| 数量 \| 描述 \| 备注`、技术规格的「标签—值」两列）还原成**无边框表格**，改一格文字不会带动别的列。列位按各格左边界聚类得出，不靠找空白通道——扫描件里相邻两列常常只差 1.5% 页宽，通道法会把它们并掉 |
| **表头与跨页续表** | 首行全是短标签就认作表头：加粗，并标记 `w:tblHeader`，表格跨页时 Word 自动重复。下一页开头若列数列位都对得上，直接续到上一张表里，页码标记做成表内整行，不把表切断 |
| **格内折行归位** | 单元格里的折行（`supplied by the` / `customer`）并回同一格，不会因为缩进几个字就凭空多出一列；散文行（`需方：XX ␣␣ 签订时间：YY`）与表格列位对不上，会被挡在表格区外 |
| **数学分式** | 上下叠排的分式（`(Smax-Smin) / Smax`）还原成**真正的 Word 公式**（OMML），显示为上下叠排、双击可进公式编辑器，不是拿斜杠拼出来的文本。分数线靠页图像素判定——峰值墨迹覆盖 >60%、厚度 ≤5 px、上下 3–4 px 处近乎全白，密排汉字行和表格框线都不会误判 |
| **续行合并** | 被 OCR 拆断的长段落重新接回一段。判据是「上一行是否排到右边界」——没排满的行绝不吸收下一行，这样小标题不会被吞进正文 |
| **项目符号找回** | OCR 会直接丢弃 `•` 这类图形符号，靠「缩进超出正文基准」把列表项还原出来 |
| **动态行距** | 空行阈值按每页实际行距中位数计算，中英文混排、不同扫描分辨率都能自适应 |
| **噪声剔除** | 骑缝章、手写签名常被识别成乱码（如把印章读成「泊上场」），按「短字符串 + 低置信度」剔除。左右页边被裁掉的竖排印记碎片不看置信度直接剔——它们能识别到 0.99，却会横跨上下两行、把两行粘成一行 |
| **标题分级** | 识别 `一、` `1.1` `A.` `22.` 等编号形态，以及无编号的下划线小标题 |
| **横版原件** | 原件多数页是横版(横向 A4、Excel 打印件)时，输出的 Word 自动用横向页面——横版表格塞进竖版 A4 只能把字缩成蚂蚁 |
| **导出 Excel** | 同一套版面判定另出一份 `.xlsx`：**只导表格**，全部排在一张工作表里依次往下，每张表上方一行灰色「原第 N 页」标注——这行**跨整张表的宽度合并居中**，标题行同理，它们是分隔带不是数据，不合并就会看着像第一列多了个怪值。跨页续表接成一张连续矩形、标注写成「原第 53–56 页」——中间夹一行页码标记，筛选和透视就废了。纯数字单元格存成真数字（小数位用数字格式保住），编号型号这类长串数字留文本，免得掉前导零或变成科学计数法 |

## 使用

### 方式一：下载现成程序（推荐）

到 [Releases](../../releases) 下载对应平台的包：

| 平台 | 下载 | 说明 |
|---|---|---|
| Windows | `pdf2doc-windows.exe` | 下载即运行，无需解压；也可把 PDF 直接拖到图标上 |
| macOS | `pdf2doc-macos.dmg` | 打开后把「扫描件转Word」拖进 Applications；首次启动需**右键 → 打开**（未做代码签名，直接双击会被拦） |
| Linux | `pdf2doc-linux` | `chmod +x pdf2doc-linux && ./pdf2doc-linux` |

> 资产名是 ASCII 的：GitHub Release 只保留 `[A-Za-z0-9._-]`，中文文件名会被吃掉。程序本身仍叫「扫描件转Word」。

界面：把 PDF（或整个文件夹）拖进左侧列表 → 点「开始转换」。

**目标格式逐文件可选**（默认 Word）：列表上方的下拉框决定新拖进来的文件用哪种格式，
选中若干项后点「应用到所选」可批量改（一项都没选＝全部）；单个文件**双击**即可循环切换，
**右键**可直接指定。每行都写着 `文件名 → Word / Excel(只导表格) / Word + Excel`，转换前一眼能核对。

### 方式二：从源码运行

```bash
pip install -r requirements.txt

python gui.py                          # 图形界面
python convert.py 文件.pdf              # 命令行，可跟多个文件（默认出 docx）
python convert.py 文件.pdf --to xlsx    # 只导表格到 Excel；--to both 两份都要
python convert.py --rebuild 目录        # 跳过 OCR，用缓存重新出文件（调参数时用）
python convert.py 文件.pdf --debug      # 额外生成版面调试图
```

> `--rebuild` 很有用：OCR 是最慢的一步，调完参数后用它秒出新版本，不必重跑识别。

## 示例

`examples/` 下有一份**合成的**扫描件示例（内容全部虚构，与任何真实合同无关）：

```bash
python convert.py examples/sample_scanned.pdf --to both   # 生成同名 .docx 与 .xlsx
python examples/make_sample.py                            # 需要时可重新合成这份示例 PDF
```

`sample_scanned.pdf` 是纯图像、无文字层的三页 A4，带轻微歪斜与噪点，覆盖了中英对照、
`1.` / `1.1` / `三、` 编号层级、「标签—值」多列版面、项目符号列表、页眉页脚与印章签名，
第 3 页是一张**画了框线的供货清单**：一格里排两行字、「备注」跨 3 行合并、「合计」跨 4 列合并。
`sample_scanned.docx` 是它的转换结果，`sample_scanned.xlsx` 是同一份文件的 Excel 输出（5 张表），
可以直接打开看效果——第 3 页那张表在两种格式里都保持了原来的合并。

## 参数说明

界面「参数」区对应引擎里的阈值，**改不出效果时优先动这两个**：

| 参数 | 默认 | 什么时候调 |
|---|---|---|
| **续行判定** | 0.78 | 段落被错误粘成一坨 → **调高**；本该连起来的句子被拆断 → **调低** |
| **列间空白** | 0.035 | 多列版面没被识别成表格 → **调低**；正文里的词间距被当成列、正文被做成表格 → **调高**（单位是占页宽的比例） |
| 识别精度 | 2560 px | 小字/密排识别不准 → 调到高精度；追求速度 → 调到快速 |
| 项目符号缩进 | 0.030 | 列表项没被识别 → 调低；正文被误判成列表 → 调高 |
| 印章置信度 | 0.88 | 印章乱码混进正文 → 调高；正常短词被误删 → 调低 |

其余开关（页眉/页脚/印章剔除、页码标记、多列表格还原、**照框线还原表格**）按需勾选。
「照框线还原表格」默认开启；只有原件真画了框线才会生效，没框线的页面照旧走按空白判列那套。
个别扫描件框线断得太厉害、被还原成一堆碎格子时，关掉它退回旧行为。

## 出问题时怎么查

| 手段 | 位置 | 说明 |
|---|---|---|
| **执行日志** | 界面底部「执行日志」区（可拖大、可复制/保存） | 每页识别了多少行、划了几个块、剔了多少噪声，逐条落在这里 |
| **错误详情** | 工具栏「错误详情」按钮 | 出错不闪退：完整 traceback 收进弹窗，可一键复制或存成文件 |
| **版面调试图** | 参数 → 版面 → 生成版面调试图，或 `--debug` | 输出到 `.pdfrec_cache/debug/`，把识别框和块划分画回页图 |

调试图的配色：蓝框=正文行，灰框=页眉页脚，**红框划叉=被当噪声剔除**，绿框=表格区（标注 `TABLE 4col`
即判出 4 列），橙框=正文区；青色竖线画在每个列起点上，洋红竖线是 `full_line` 阈值线。
**洋红粗框=框线表格还原出来的单元格**（粗的是合并格，标注 `GRID 20x13 merged 25`）。
列切错了、段落该合没合、印章误删正文，看一眼就知道该动哪个参数。

**单页失败不会毁掉整篇**：某页图像损坏或版面异常时，该页记一条错误、在 Word 里留一行红色
`[第 N 页解析失败]` 占位，其余页照常输出。批量转换里某个文件整体失败也只跳过它，队列继续走完。

## 自己构建

PyInstaller **不支持交叉编译**——Windows 的 exe 必须在 Windows 上打，macOS 的 .app 必须在 macOS 上打。

```bash
pip install -r requirements.txt pyinstaller
python -c "from rapidocr import RapidOCR; RapidOCR()"   # 先下载模型, 否则打出空壳
pyinstaller pdfrec-gui.spec --noconfirm                  # 图形界面版
pyinstaller pdfrec.spec --noconfirm                      # 纯命令行版
```

仓库已配好 GitHub Actions（`.github/workflows/build.yml`）：打一个 `v*` 标签即可自动产出三平台安装包并发布 Release。

体积参考：命令行版约 137 MB，图形界面版约 165 MB（含 30 MB OCR 模型 + PySide6）。

## 已知限制

- **签名、印章、二维码、页眉页脚会被剔除**（默认行为，可在参数里关闭）。转出的 Word 若要作为正式文件，签章需另行处理。
- **原文的下划线、字符级格式不还原**，只保留标题加粗与段落结构。
- **图纸、示意图不会带过来**，只提取其上的文字。
- **公式只还原一层分式**：根号、积分、求和、上下标不识别，嵌套分式也只当一层处理。
- **Excel 输出只有表格**：正文段落、标题、项目符号一概不进 `.xlsx`，要整篇内容请用 Word（或选 Word + Excel
  两份都出）。分式在 Excel 里摊平成 `(Smax-Smin)/Smax` 这样的一行文本，OMML 公式只有 Word 版有。
- **框线还原受制于原件真有框线**：Excel 导出件里两个并排的合并表头之间常常压根没画线（比如
  `交易所信息 | 客户交易相关信息`），没有线就没法判边界，这两格会并成一格。
- **窄列里的小字可能串格**：OCR 的行检测会把相邻两个窄格的字连成一行，落到网格里就成了一格里
  夹着另一格的字。列宽越窄、字号越小越容易，遇到时对照原件核一下。
- OCR 在型号、公差这类**密集数字**上仍可能出错，重要文件建议人工抽查一遍。
